## 1. 项目概述

**项目定位与核心价值：**
`pi-mono` 是一个专注于构建 AI 智能体和管理大语言模型（LLM）部署的全栈工具集 Monorepo（单体仓库）。其核心价值在于**抽象并统一了碎片化的 LLM 生态**，提供从底层多模型 API 封装、智能体运行时，到上层终端交互（CLI）和 Web 界面的端到端解决方案。项目以“不严肃”的命名（如域名 `shittycodingagent.ai`）掩盖其扎实的工程设计，旨在降低开发者构建、部署和管理 AI 编码助手及自动化智能体的门槛。

**主要功能列表：**
- **多供应商 LLM 统一接口**：支持 OpenAI、Anthropic、Google 等主流大模型。
- **智能体运行时**：具备工具调用和状态管理能力的 Agent 核心。
- **交互式编码智能体 CLI**：直接在终端运行的 AI 编码助手。
- **Slack 机器人集成**：将消息代理给 pi 编码智能体，实现远程协作。

## 3. 核心功能/组件分析

**主要功能模块：**
1. **`packages/ai` (LLM 统一网关)**：屏蔽不同大模型厂商 API 的差异，向上层提供统一的 `chat/completion` 和 `tool-calling` 接口。
2. **`packages/agent` (智能体大脑)**：实现 ReAct（Reasoning and Acting）模式，管理对话上下文、工具调用循环和状态机。
3. **`packages/coding-agent` (执行终端)**：具体实现“编码”这一垂直场景，内置文件读写、代码搜索、终端执行等工具集。
4. **`packages/tui` & `packages/web-ui` (表现层)**：`tui` 针对终端环境实现虚拟 DOM 或双缓存机制的差异化渲染，保证流式输出时的画面不闪烁；`web-ui` 提供可复用的 Web Components。
5. **`packages/mom` (生态拓展)**：将 Agent 能力接入 Slack，实现异步的人机协同或机器人触发式编码。

**组件关系：**
数据流自下而上：`pi-ai` 获取模型能力 -> `pi-agent` 接收指令并结合 `Tools` 进行推理循环 -> `pi-coding-agent` 调用 `pi-tui` 渲染交互界面，同时调用本地开发工具执行代码修改 -> `pi-mom` 作为外部触发器，通过 API 调用 `pi-coding-agent` 的无头模式。

## 4. 技术实现亮点

- **FFI 机制的引入 (`koffi`)**：在主要由 JS 主导的 AI 应用层引入 FFI，极有可能用于解决终端原生控件交互、高性能字符串处理（流式输出解析）或直接调用本地编译的模型推理库，突破了纯 Node.js 的性能瓶颈。
- **即时编译集成 (`jiti`)**：作为内部依赖深度集成，允许 Agent 在运行时动态加载、编译和执行用户编写的工具脚本，这对于需要动态扩展能力的 Coding Agent 来说是极佳的实践。
- **终端差异化渲染引擎**：自研 `pi-tui` 并强调“differential rendering”，说明其解决了终端流式输出（Token-by-Token）时的画面撕裂和闪烁问题，提供了媲美原生 GUI 的顺滑体验。
- **状态与工具调用的解耦**：Agent 核心不绑定具体工具，而是通过运行时注入，使得同一个 Agent 内核既能做编码助手，也能做 Slack 机器人后端。

**目标用户：**

- 需要统一管理多套 LLM 并进行 Agent 编排的架构师。

**应用场景：**

- **异步代码任务分发**：通过 Slack 发送指令，Agent 在服务器端无头执行代码修改并提交 PR。
- **多模型对比测试平台**：利用统一的 `pi-ai` 接口，快速切换底层模型验证其编码能力。
