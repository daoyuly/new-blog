# 华为云 CodeArts Doer 研发智能体实践：从提示工程到多智能体协同的确定性演进

## 导语

软件研发正加速向 Agent Economy 演进。在这个范式下，研发模式正从高度依赖提示词工程的“概率性生成”，转向由 Agent 驱动工具链进行“确定性执行”。华为云 CodeArts Doer 研发智能体正是这一趋势下的工程化实践。它基于大模型与多智能体协同，覆盖软件研发全流程，通过人机协作、动态认知进化与端到端安全合规，实现研发提效与质量守护。本文将拆解 CodeArts Doer 的核心架构、工程挑战与落地实践，为团队构建研发智能体提供可执行的路径参考。

## 核心问题与挑战

在将大模型与 Agent 深度引入研发流程的过程中，我们面临四个维度的核心挑战：

1. **Agent 的天然局限与失控风险**：Agent 普遍存在环境感知不足、幻觉、过度工程化与重复造轮子等问题。实践证明，完全依赖 Agent 生成的系统几乎不可维护，连锁 Bug 与安全漏洞频发。
2. **项目上下文缺失与知识孤岛**：传统研发知识高度碎片化，人工查找效率极低。大模型若缺乏项目级上下文，代码生成极易跑偏；而长上下文交互又面临记忆共享与断链的稳定性难题。
3. **多 Agent 协同的工程化鸿沟**：从单 Agent 迈向多 Agent 并行协同，场景复杂度剧增。多团队同步开发部署、长上下文统一记忆、交互断链恢复等问题，成为系统稳定性的最大威胁。
4. **前后端开发范式的根本性转变**：前端交互需从传统的“确定性交互”转为“模型数据驱动交互”，面对不可控的模型输出，原有的开发与调试范式面临失效。

## 方案与实践

针对上述挑战，CodeArts Doer 形成了一套从架构策略到场景落地的完整解法。

### 人机协作与小步敏捷迭代

打破“Agent 万能”的幻觉，确立开发者的主导地位。开发者负责批判性思维、准确定义问题、制定规则与提供丰富上下文；Agent 负责执行。采用敏捷版本迭代模式，每次交付一个可稳定运行的完整版本，坚决避免一次性生成庞大且无法维护的半成品。

### 动态认知进化与 ArchRAG 知识沉淀

为解决知识碎片化与上下文跑偏，CodeArts Doer 构建了强大的研发知识库（基于近百亿行代码实践），并引入 **ArchRAG 关联知识仓库**与**动机性遗忘机制**。通过分级记忆，智能裁剪长上下文中的低价值信息，保留核心项目约束，显著提升模型在复杂项目中的代码采纳率与生成准确度。

### 全场景研发痛点智能解法

在具体研发环节，Doer 针对痛点逐一击破：
- **需求管理**：针对一句话需求与格式不规范，大模型自动进行需求润色与一键分解，打破依赖长期经验的瓶颈。
- **编码与审查**：针对项目架构复杂与动态依赖混乱，提供全局代码理解、智能审查与一键修复；日常研发支持知识问答、代码生成、注释与翻译。
- **测试与运维**：针对测试用例编写耗时与报告繁杂，实现测试意图智能分析（天级缩至分钟级），并提供报告智能解读与修复建议。
- **问题定位**：针对故障定位困难，内置 5 万+海量经典案例，覆盖 1000+ 错误场景，实现智析故障与迅定乾坤。

### 多 Agent 协同技术底座与前端范式重构

在技术底座层面，CodeArts Doer 引入 **A2A（Agent-to-Agent）与 MCP 协议**构建多 Agent 协同与工具集成。针对长连接与稳定性问题，基于 **SSE（Server-Sent Events）**解决弱网断连与状态不一致。在前端层面，构建消息驱动的多 Agent 交互架构与 AI 交互范式，动态适配模型行为，消解前端从确定性转向数据驱动时的开发摩擦力。

## 原则/方法论沉淀

在研发智能体的建设与落地过程中，我们沉淀了以下四条核心原则：

1. **单 Agent 优先，多 Agent 渐进**：优先挖掘单 Agent 能力边界；仅在复杂任务时引入多 Agent，且必须重点设计分工边界与错误恢复机制。
2. **小步交付，拒绝半成品**：每次迭代必须交付可稳定运行的完整版本，通过 PDCA 验证闭环，遏制大模型的过度工程化倾向。
3. **全流程无断点，安全合规前置**：端到端守护研发质量，线上问题前置拦截，杜绝 Agent 越权操作与数据泄露。
4. **工具向队友演进**：研发工具向“研发队友”转变，Agent 接管非编码的脏活累活，让开发者聚焦于架构决策与业务逻辑。

## 总结与行动建议

研发智能体并非替代开发者，而是通过接管非核心环节，迫使开发者向更高维的架构设计与系统思考演进。对于准备引入研发智能体的团队，建议采取以下行动：

1. **重构上下文基建**：立即着手清理与关联研发元数据，构建项目级 RAG，这是提升代码采纳率的地基。
2. **划定 Agent 边界**：从测试用例生成、代码注释等低风险场景切入，严格限制 Agent 在核心架构决策中的自主权。
3. **建设协同底座**：尽早引入 A2A/MCP 等标准协议，基于 SSE 规划长连接与断链恢复策略，为多 Agent 并行打牢基础。
4. **重塑开发者能力模型**：培训团队从“写代码”向“定规则、给上下文、审结果”转型，强化人机协作中的批判性思维。

## 开放问题与延伸方向

1. **ArchRAG 关联知识仓库与动机性遗忘机制的具体触发条件与上下文保留比例如何量化定义？**——涉及动态记忆阈值机制，需结合具体业务实验确定量化基线。
2. **A2A 与 MCP 协议在长上下文交互中，如何处理弱网环境下的 SSE 断连与状态不一致问题？**——依赖 SSE 重连策略与状态快照恢复机制，是工程稳定性的关键。
3. **开发者将非编码环节交由 Agent 接管，长期是否会削弱对系统全局架构的掌控感与业务直觉？**——需通过保留架构设计与规则制定权来对冲能力退化风险。
4. **前端从确定性交互转为模型数据驱动交互，面对不可控的模型输出，开发者的调试焦虑如何缓解？**——呼唤更精细的模型输出边界约束与沙箱调试工具。
5. **多 Agent 并行协同下，若某个子 Agent 产生幻觉并传播，如何防止错误雪崩导致整个迭代版本不可用？**——需在多 Agent 间设置互审校验与熔断机制。
6. **动机性遗忘机制在裁剪长上下文时，是否存在误删关键项目约束从而导致代码生成跑偏的致命弱点？**——遗忘机制需引入关键性校验与人工确认兜底。
7. **人机协作的小步敏捷迭代模式，为何能有效抑制大模型在复杂任务中常见的过度工程化倾向？**——小步迭代天然限制了大模型的单次生成边界，通过快速纠偏防止跑飞。
8. **研发工具向“研发队友”演进，除了提效，在提升开发者心流体验与团队留存率方面有何潜在收益？**——Agent 承担脏活累活，开发者更易进入深度思考心流，改善研发体验。
9. **除了 A2A/MCP 协同，是否可引入类似红蓝对抗的双 Agent 互审架构来增强系统的自纠错与防幻觉能力？**——红蓝对抗是极具潜力的自纠错架构演进方向，值得探索。
10. **在落地多 Agent 系统时，单 Agent 能力挖掘与多 Agent 编排的投入优先级应遵循怎样的动态评估原则？**——遵循“先榨干单 Agent，再编排多 Agent”的 ROI 评估原则。
11. **面向 Agent Economy 演进，当前 CodeArts Doer 架构最急需补齐的端到端安全合规工程验证环节是什么？**——急需补齐 Agent 行为的越权拦截与数据流转审计闭环。
