## 一句话总结

NanoClaw 是一个主打"安全与轻量"的 AI Agent 运行框架，核心思路是将每个 AI Agent 隔离在独立的 Docker 沙箱 + MicroVM 中，实现操作系统级别的安全隔离。整个代码库仅 3.49 万 Tokens，开发者可以单次上下文完整阅读，适合需要安全运行 AI 自动化任务的场景。

## 1. 项目概述

NanoClaw 的核心价值在于为 AI Agent 提供操作系统级别的安全沙箱环境。与市面上动辄数十万行代码、依赖庞大的 Agent 框架不同，NanoClaw 主张"极简主义"与"可控性"——将每个 AI Agent 隔离在独立的 Docker 容器与微型虚拟机中，从根本上解决 AI 代理执行系统级操作时的安全风险，同时保持毫秒级启动速度和极高的代码可读性。

**主要功能：**

- **Docker 沙箱隔离**：每个 Agent 运行在独立容器内，具备 Hypervisor 级别隔离性
- **轻量化核心**：代码库约 3.49 万 Tokens，仅占 17% 上下文窗口，易于理解和审计
- **跨平台支持**：支持 macOS（Apple Silicon）和 Windows（x86/WSL），提供一键安装脚本
- **定时任务调度**：集成 cron 解析，支持 Agent 定时自动化执行
- **结构化日志与持久化**：基于 Pino 的高性能日志与 better-sqlite3 的本地数据持久化

## 2. 技术栈分析

| 层面 | 技术选型 | 选型理由 |
|------|---------|---------|
| 运行时 | Node.js + 原生模块 | 轻量、跨平台、生态丰富 |
| 沙箱 | Docker + MicroVM | Hypervisor 级隔离，毫秒级启动 |
| 持久化 | better-sqlite3 | 同步高性能，零配置，无 ORM 负担 |
| 任务调度 | cron-parser | 轻量 cron 表达式解析 |
| 日志 | pino + pino-pretty | 极低开销 JSON 结构化日志 |
| 配置校验 | zod | TypeScript-first 运行时校验 |
| 配置格式 | yaml | 人类友好的配置文件 |

**架构特点：**

- **微内核 + 外围隔离**：主进程仅负责调度、配置解析和日志记录，Agent 执行逻辑全部下沉到独立 Docker 沙箱
- **去中心化内存模型**：摒弃单进程多 Agent 共享内存模式，Agent 间通过沙箱边界物理隔离，避免内存污染和提权攻击

项目依赖极少，选用的库均以"底层、高性能、少封装"著称——用 `better-sqlite3` 而非 ORM，用 `zod` 运行时校验而非类装饰器，追求"零负担"依赖树。

## 3. 核心组件分析

**五大功能模块：**

1. **沙箱管理器** — Docker 容器生命周期管理（创建、启动、暂停、销毁）+ 底层 MicroVM 通信
2. **任务调度引擎** — 基于 cron-parser，按时触发特定 Agent 沙箱执行
3. **配置与校验中心** — 读取 yaml 配置，通过 zod 校验 Agent 配置合法性，确保注入沙箱的参数安全
4. **状态持久化层** — better-sqlite3 记录 Agent 运行状态、历史输出和上下文，主进程崩溃后数据不丢失
5. **可观测性模块** — pino 流式输出结构化日志，便于接入 ELK 或 Grafana Loki

**关键组件：**

- **Sandbox Runtime（沙箱运行时）**：项目核心壁垒。不只是简单的 `docker run`，而是结合 MicroVM，确保即使容器内发生恶意逃逸，也仅限于微型虚拟机范围内，不影响宿主机。
- **Validation Schema（校验模式）**：主进程与沙箱之间的"防火墙"，所有传给 Agent 的指令和工具权限均需通过 Zod 严格校验。

**数据流：**

```
配置中心解析请求 → Zod 校验合法性 → 调度引擎决定执行时机
→ 沙箱管理器拉起独立容器 → Agent 在容器内执行并产生数据
→ 数据通过持久化层存入 SQLite → 全程日志由 Pino 记录
```

整个流程单向且解耦。

## 4. 技术亮点

### OS 级隔离替代应用级隔离

传统 AI Agent 框架多采用黑名单/白名单机制（应用级隔离）限制 AI 行为，一旦存在逻辑漏洞极易被 LLM Prompt 绕过。NanoClaw 直接降维到 OS 级别，利用容器和虚拟机技术进行物理隔离，从根本上杜绝越权操作。

### 极致的上下文窗口控制

代码量严格控制在 3.49 万 Tokens 以内，开发者甚至 AI 本身可以在单次上下文中完整阅读整个项目代码，极大降低理解和二次开发门槛。

### 设计模式

- **隔离模式**：通过沙箱实现状态与执行隔离
- **契约模式**：Zod 定义清晰数据契约，确保模块间强类型安全
- **微服务微缩版**：单个 Agent 视为微服务，主进程作为 API Gateway

## 6. 借鉴点

**技术层面：**

1. **AI Agent 沙箱化部署** — 将 AI 的"大脑"（LLM API）与"手脚"（执行环境）物理分离，是 Agent 走向生产环境的必经之路
2. **Zod 运行时配置校验** — 处理复杂 Agent 配置（权限、网络、挂载点）时，比 TypeScript 静态类型检查更可靠
3. **SQLite 作为轻量级 Agent 记忆库** — `better-sqlite3` 兼顾性能与零配置，是单机版 AI 应用最佳实践

**产品层面：**

1. **"可读性优先"哲学** — AI 时代代码库大小直接决定 AI 辅助编程效率，控制 Token 数量是前瞻性决策
2. **降维安全策略** — 不与应用层漏洞死磕，利用容器/虚拟机技术直接降维解决
3. **渐进式部署体验** — `curl | bash` 一键安装脚本降低尝试成本

**工程实践：**

1. **结构化日志先行** — 早期引入 Pino，调试复杂 Agent 行为时有完整执行链路日志
2. **极简依赖管理** — 仅 6 个核心库，减少供应链攻击风险和版本冲突
3. **跨平台沙箱适配** — macOS（Apple Silicon）和 Windows（WSL）不同底层架构提供定制化方案

## 常见问题

**NanoClaw 和 OpenClaw 有什么区别？**

NanoClaw 走极简路线（3.49 万 Tokens），核心聚焦安全沙箱隔离；OpenClaw 是功能完整的 Agent 平台，支持多通道通信、Skills 系统等。两者定位不同，NanoClaw 适合需要轻量安全隔离的场景，OpenClaw 适合需要完整 Agent 能力的场景。

**NanoClaw 的安全隔离是怎么实现的？**

通过 Docker 容器 + MicroVM 双层隔离实现。Agent 在容器内执行，即使容器逃逸也仅限于微型虚拟机范围，不影响宿主机。所有传给 Agent 的指令和工具权限还需通过 Zod 严格校验。

**NanoClaw 适合什么场景使用？**

适合需要安全运行 AI 自动化任务的场景：自动化代码审计、安全数据分析、定时网络爬虫、个人 AI 助理后端等。特别适合对安全性有高要求的开发者和安全工程师。

**NanoClaw 是免费的吗？**

是开源项目，支持 macOS（Apple Silicon）和 Windows（WSL）平台，提供一键安装脚本。
