## Agent Harness 成熟度模型 (AHMM)

| 级别 | 名称 | 特征 | 代表项目 | 2026现状 |
|------|------|------|---------|---------|
| L1 | 能力验证 | 单场景 Demo 可跑 | BabyAGI, Crawl4AI | 已跨越 |
| L2 | 组件化 | 模块可组合替换 | LangChain, CrewAI, OpenAI Agents SDK | 当前主流 |
| L3 | 可观测 | 链路追踪+评估闭环 | LangSmith, OpenClaw, Weave | 部分达到 |
| L4 | 弹性伸缩 | 动态调度+容错自愈 | Dify(企业版), Coze, Amazon Bedrock Agent | 少数达到 |
| L5 | 自治运维 | Agent 自监控自修复 | Google A2A, AG2 | 探索中 |

**定义：** 衡量 Agent 开发框架/运行时从原型到生产就绪的五级成熟度模型。L1 能力验证 → L2 组件化 → L3 可观测 → L4 弹性伸缩 → L5 自治运维。大多数框架当前处于 L2-L3 之间。

## Agent 编排四范式

| 范式 | 特点 | 适用场景 | 代表实现 | 局限 |
|------|------|---------|---------|------|
| 线性链 (Chain) | 固定顺序，简单可靠 | 单任务Pipeline | LangChain Chain, OpenAI Agents SDK | 不支持分支 |
| DAG (有向图) | 并行+依赖，高效 | 多步骤编排 | LangGraph, ControlFlow | 需预定义拓扑 |
| 事件驱动 (EDA) | 解耦+实时，灵活 | 响应式Agent | Inngest, Trigger.dev | 调试复杂 |
| 自治协作 (Autonomous) | Agent自决策，弹性 | 复杂探索任务 | AG2, CrewAI, Google A2A | 可控性弱 |

**定义：** Agent 编排架构的四种基本范式：线性链（Chain）、有向无环图（DAG）、事件驱动（Event-Driven）、自治协作（Autonomous）。实际系统通常是多种范式的混合。

## 2. 编排模式分析（基于 Agent 编排四范式）

今日动态反映出编排趋势正从简单的线性链向**事件驱动**和**自治协作**两极深化，同时引入了**并行计算**概念。

*   **线性链**：适合简单任务（如 RAG 问答），但在今日动态中占比下降，无法满足复杂业务逻辑。
*   **DAG（有向无环图）**：在需要明确流程控制和确定性输出的场景中胜出。例如 TradingAgents 中的财报分析流程，适合有严格依赖关系的工作流。
*   **事件驱动**：适合需要高度解耦和异步处理的系统。当 Agent 需要响应外部环境变化（如实时行情、用户打断）时，事件驱动是唯一解。
*   **自治协作**：**今日最大亮点**。MetaGPT 的“AI 软件公司”和 CrewAI 的角色扮演均属此类。结合《Alignment by Confident Debate》论文，自治协作在需要多视角论证和创意生成的场景下胜出。

**混合编排的最佳实践**：
“外层 DAG/事件驱动 + 内层自治协作/并行”。即：在系统宏观层面使用 DAG 确保业务流程的确定性和可审计性；在具体节点内部，部署自治协作的 Agent 团队（如 Debate 模式或 Parallel Teams）进行深度思考和方案生成；最后由 DAG 层面的 Router Agent 进行结果收敛和干预。

## 4. FAQ：关于 Agent Harness 的常见问题

**Q1: 在 Agent 开发中，应该优先选择成熟框架（如 LangChain/AutoGen）还是从零构建？**
**A:** 强烈建议优先选择成熟框架。Agent Harness 的核心难点在于状态管理、工具调用容错和消息流路由。LangChain 等平台已沉淀了大量工程实践（如重试机制、并发控制）。从零构建不仅耗时，且极易在生产环境的边缘场景下崩溃。除非有极高的定制化要求和极简的架构需求，否则应站在巨人的肩膀上。

**Q2: 多智能体协作中，如何避免“死循环”和“幻觉共振”？**
**A:** 这是自治协作范式的核心痛点。解决方案有三：一是引入《Alignment by Confident Debate》中的机制，设定明确的终止条件（如最大轮次、置信度达标）；二是采用“并行团队”替代“串行辩论”，即让多个 Agent 独立解决同一问题，再由裁判 Agent 选取最优解，避免相互误导；三是强制引入外部工具验证（如代码执行、搜索检查），用客观数据打破幻觉闭环。

**Q3: 如何在生产环境中评估和监控 Agent 的表现？**
**A:** 传统的准确率指标不适用于 Agent。应采用“因果评估”与“过程可观测”结合的方法。首先，部署全链路追踪（如 LangSmith），记录每一步的 Thought、Action 和 Observation。其次，参考《Knowing When to Intervene》，实施随机化干预测试，评估 Agent 在被切断某工具或修改某输入后的行为表现，以此判断其决策逻辑的鲁棒性，而非仅仅看最终输出。
