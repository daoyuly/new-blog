# WKM 项目深度分析报告

## 1. 项目概述

**WKM（World Knowledge Model）** 是浙江大学 KG 组（zjunlp）开源的一个学术研究项目，对应论文《Agent Planning with World Knowledge Model for Online Large Language Models Agents》（arXiv: 2405.14205）。项目针对的核心问题是：LLM Agent 在交互式规划任务中盲目“试错”，缺乏对环境结果（World Knowledge，即状态转移与反馈）的先验知识，导致规划效率低、成本高。

核心价值在于引入一个轻量级的“世界知识模型”，用于预测 Agent 在环境中执行动作后的状态变化和反馈，从而在规划时提前预判后果、回溯次优轨迹，实现无需在线交互的“前瞻式规划”。

主要功能列表：
- 从交互轨迹中自动构建世界知识（World Knowledge Build）
- 基于世界知识训练 LLM Agent（LoRA 微调）
- 在 WebArena、WebShop、SciWorld、ALFWorld 等经典 Agent 基准上评估
- 支持知识蒸馏（大模型 Teacher → 小模型 Student）
- 提供预训练模型（HuggingFace zjunlp/wkm 系列）

## 2. 技术栈分析

**技术与框架：**
- 训练模块：基于 **LLaMA-Factory**（LoRA/QLoRA 微调框架）
- 推理模块：改编自 **ETO**（Trial-and-Error 推理框架）
- 模型底座：LLaMA2、Mistral、Vicuna、Gemma 等开源 LLM（7B 级别为主）
- 推理服务：**FastChat** + **LangChain** 集成调用开源模型
- 基线对比：ReAct、Reflexion、NAT、ETO、TS、ToT 等 Agent 方法

**架构特点：**
- 典型的“研究型代码”架构：`WKM/`（训练）、`inference/`（推理评估）双模块分离，基线代码按方法分目录组织
- 流水线式设计：轨迹收集 → 世界知识抽取 → WKM 训练 → Agent 训练（WKM 增强数据）→ 在线评估
- 双模型协作：Agent 模型负责生成候选动作，WKM 模型负责预测环境反馈，二者交替迭代

**依赖关系：** torch/transformers/peft（训练），FastChat（服务），LangChain（编排），各环境仿真器（WebShop、ALFWorld 等）。

## 3. 核心功能/组件分析

1. **World Knowledge Build（知识构建）**
   - 利用 Teacher Agent（较强 LLM）在环境中交互，产生成功/失败轨迹
   - 从轨迹中抽取“状态-动作-结果-反馈”结构化世界知识对
   - 核心产物：既有环境反馈文本（如搜索结果、系统提示）也有状态转移信息

2. **Model Training（模型训练）**
   - 用世界知识数据训练 WLM/WKM（预测未来状态与反馈）
   - 用“Agent 模型 + WKM 模型”联合采样生成增强轨迹，训练 Student Agent
   - 知识蒸馏机制：LLaMA2-70B Teacher → 7B Student，实现成本降低

3. **Inference & Evaluation（推理评估）**
   - 规划时 WKM 先行预测每步结果，Agent 据此打分/选择/回溯（前瞻+回溯机制）
   - 支持在线交互场景下的自动评估与指标统计
   - 覆盖四大基准：WebShop（电商购物）、WebArena（真实网页）、SciWorld（科学实验）、ALFWorld（具身家务）

**组件关系：** 知识构建为训练提供数据 → 训练产出 WKM 与 Agent 双模型 → 推理阶段二者协同完成前瞻式规划，形成闭环。

## 4. 技术实现亮点

**创新点：**
- **首个将"World Model"概念系统引入 LLM Agent 规划的工作之一**：将 Model-based RL 思想（学习环境动态模型避免真实交互）迁移到 LLM Agent 场景
- **前瞻+回溯规划机制**：WKM 预测候选轨迹结果，Agent 可在不与环境交互的情况下预筛/回溯，显著降低在线交互成本与试错代价
- **知识蒸馏降低成本**：先用昂贵的大模型构建世界知识，再蒸馏到 7B 小模型，兼顾效果与推理开销

**设计模式与最佳实践：**
- 站在巨人肩膀上的工程策略：训练复用 LLaMA-Factory、推理复用 ETO，快速验证学术想法
- 统一的轨迹数据格式，��知识抽取、训练、评估各环节解耦
- 提供完整 pipeline（从数据到模型到评估），保证论文可复现性

## 5. 产品意义和应用场景

**解决的问题：**
- LLM Agent 盲目试错、无效交互多、token 成本高的问题

- 在线环境交互昂贵/不可逆场景下的规划安全问题

**目标用户：**
- Agent/LLM 研究人员（学术复现、基线对比）

- 探索低成本小模型 Agent 方案的团队

**应用场景：**
- 网页自动操作（电商下单、信息检索）
- 科学实验仿真规划
- 具身智能任务规划
- 任何需要预测环境反馈的交互式决策系统

## 6. 借鉴点

**技术层面：**
1. **Model-based 规划思想用于 LLM Agent**：用学习到的环境模型替代真实试错，可直接迁移到其他 Agent 框架（如 MCTS + World Model）
2. **结构化世界知识抽取 pipeline**：从自由文本轨迹中自动抽取“动作-状态-反馈”知识，是数据飞轮的典型范例
3. **大模型构建知识 + 小模型蒸馏落地**的成本分摊模式，适用于生产环境中平衡效果与成本
4. **前瞻-回溯双阶段规划**：预测-评估-回溯的控制流设计可泛化为通用 Agent 规划骨架

**产品层面：**
1. **学术开源的完整度**：论文、网页、HF 模型、X 推广、NotebookLM 音频讲解一体化传播，值得开源项目借鉴
2. **明确的 README 分区**（构建/训练/评估三段式）使新用户能快速对齐心智
3. **多基准覆盖**证明通用性，提升方法的可信度和采用意愿
4. 致谢与基线代码的开放整合，形成对社区友好的研究生态

**工程实践：**
1. **复用成熟框架（LLaMA-Factory、ETO、FastChat）** 而非重复造轮子，大幅缩短研究迭代周期
2. **训练/推理模块解耦**，训练产物可直接接入推理评估，接口清晰
3. **基线方法按目录隔离**（ReAct、Reflexion、NAT、ETO 各自独立），便于公平对比和增量替换
4. 使用 LangChain + FastChat 的本地开源模型服务化方案，避免对闭源 API 的硬依赖

## 7. 待深入研究

1. **世界知识的表示形式消融**：README 层面看不到知识是纯文本还是结构化格式，可深入源码分析不同知识粒度（环境反馈 vs. 状态转移）对效果的影响
2. **WKM 与 Agent 的联合优化**：当前是两阶段训练，是否可以端到端联合训练或交替迭代（self-play 式）提升上限
3. **与 MCTS/Tree Search 的结合**：WKM 本质提供了模拟器能力，可研究将其作为 rollout 模型接入 ToT/MCTS 框架的可行性
4. **世界知识的泛化与迁移**：在 WebShop 上学到的 WKM 能否零样本迁移到 WebArena？跨环境知识共享是重要研究方向
5. **与后续 World Model 工作的对比**：如 MWC、MindAgent、Video World Models 等，梳理"World Model for LLM Agent"技术演进脉络
6. **数据质量与噪声鲁棒性**：Teacher 轨迹中失败样本如何筛选、抽取的知识存在噪声时对 Student 的影响
7. **工程化落地评估**：双模型推理的延迟/吞吐开销、是否可用单模型多任务头替代，以降低部署成本
