第 5 个月建议不要再把重点放在“学习更多 Agent 框架”，而是进入真正的 **Agent Research Engineering**：把前 4 个月做出的 Runtime、Harness、Context、Memory、Inference，变成一套可以“测量 → 分析 → 改进 → 验证”的实验系统。

核心目标是：

> **从“会做 Agent”进入“会研究 Agent 为什么有效、为什么失败，以及如何系统改进 Agent”。**

这个月不建议真的去训练大模型。你的目标不是成为 RL 算法工程师，而是掌握 Agent Training / Evaluation 背后的基本机制，并能够自己搭建一套小型实验系统。

## Day 1：为什么 Agent Evaluation 比传统 LLM Evaluation 难

学习：

理解三种 Evaluation：

```text
LLM Evaluation
    ↓
单次 Response

Agent Evaluation
    ↓
多轮 Interaction
    ↓
Tool Calls
    ↓
Environment State
    ↓
最终结果
```

重点理解：

* Response-level evaluation
* Task-level evaluation
* Trajectory-level evaluation
* Tool-use evaluation
* Outcome vs Process

编码：

给你的 Agent Harness 增加：

```python
Task
Trajectory
Step
ToolCall
Observation
FinalResult
```

例如：

```python
@dataclass
class Step:
    step_id: int
    action: str
    tool: str | None
    observation: str | None
    latency: float
```

输出：

```json
{
  "task_id": "task_001",
  "success": true,
  "steps": 7,
  "tool_calls": 4,
  "latency": 8.2
}
```

# Day 10：Error Attribution

今天解决一个更难的问题：

> 一个 Agent 失败，到底是谁导致的？

例如：

```text
模型选择错 Tool
        ↓
Tool 返回错误
        ↓
模型继续错误操作
        ↓
最终失败
```

不能简单说：

> Agent Failed

而应该记录：

```text
Root Cause:
Tool Selection

Propagation:
Tool Error
→ Bad Observation
→ Wrong Next Action
→ Final Failure
```

编码：

实现简单的 Failure Attribution。

先使用规则。

不要一开始搞复杂因果推理。

# Day 16：Reward Design

这是 Agent Research 很核心的一天。

例如 Coding Agent：

```text
测试通过       +1
部分测试通过   +0.5
代码无法运行    0
任务失败        -1
```

但是现实中可能出现：

```text
任务成功
但用了 50 次 Tool Call
```

所以可以设计：

```text
Reward =
Success
- λ × ToolCalls
- μ × Tokens
- ν × Latency
```

重点思考：

> Reward 会不会被 Agent “钻漏洞”？
