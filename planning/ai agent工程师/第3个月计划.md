M3建议不要简单定义成“Memory 月”。按照前两个月的路线，M3应该解决一个更核心的问题：

> **Agent 如何管理有限的 Context，并通过 Memory / Retrieval 获得长期能力，同时避免把无关信息塞回模型。**

这也是你已有积累最多、但最容易过度设计的一块。所以这个月我会刻意压缩架构，把重点放在：

**Context Engineering → Retrieval → Memory → Task Relevance → Evaluation**

而不是先造一个“认知引擎大框架”。

---

10. 如何证明 Memory 真正提高了 Agent 的任务成功率？

# Day 1：Context到底是什么

先画出一个真实 Agent 请求：

```text
System Prompt
+
User Input
+
Conversation
+
Tool Results
+
Task State
+
Memory
+
Environment
        ↓
      Context
        ↓
       LLM
```

区分：

```text
Conversation ≠ Context
Memory ≠ Context
Context ≠ Prompt
```

然后统计自己 M2 Coding Agent 的 Context 构成。

### 编码

实现：

```python
class Context:
    system
    messages
    tools
    state
    memory
```

先不要复杂化。

`docs/context-model.md`

# Week 2：Retrieval

这一周开始进入真正的 Memory 基础。

但不要先研究“认知记忆”。

> **给定一个 Query，系统到底应该把什么内容找回来？**

# Day 8：为什么需要 Retrieval

构造一个简单问题：

```text
用户过去说过1000条信息。

现在问：
“按照我的工作习惯，给我安排明天的计划。”
```

显然不能把1000条全部送进模型。

于是：

```text
Query
 ↓
Retrieval
 ↓
Relevant Information
 ↓
Context
```

今天重点理解：

> Retrieval不是“搜索”，而是Context选择。

# Day 16：Memory Write

研究：

> 什么信息应该写入长期 Memory？

建立一个简单判断：

```text
Temporary
    ↓
Should Persist?
    ↓
Memory
```

例如：

```text
“我今天有点累”
```

通常不应该变成长期偏好。

而：

```text
“以后工作日上午尽量不要安排会议”
```

可能值得保存。

# Day 18：Memory Update / Conflict

这是非常重要的一天。

例如：

```text
Memory A:
用户喜欢早起

New:
用户最近更喜欢晚上工作
```

不能简单：

```text
INSERT
```

需要：

```text
Existing Memory
+
New Evidence
 ↓
Update / Replace / Keep
```

研究：

* Conflict
* Recency
* Confidence
* Source
* Evidence

实现最简单的版本。

---

# Day 19：Task-Relevant Recall

这是M3最核心的一天。

不要：

```text
User
 ↓
所有Memory
 ↓
LLM
```

而是：

```text
Current Task
 ↓
Query
 ↓
Retrieve
 ↓
Filter
 ↓
Rank
 ↓
Relevant Memory
```

例如：

```text
用户问：
“帮我安排下周会议”

应该召回：
会议习惯
工作时间偏好
已有会议
相关项目

不应该召回：
去年去日本旅游
喜欢什么电影
小时候学校
```

实现：

```python
recall(
    task,
    memories
)
```

# M3结束时，你应该真正获得什么

M1结束：

> 我理解 Agent Runtime。

M2结束：

> 我能让 Agent 在真实环境中执行任务。

M3结束：

> **我能控制 Agent 在有限 Context 中看到什么，并能够通过 Memory 有选择地提供长期信息。**

也就是：

```text
M1
LLM
 ↓
Runtime

M2
Runtime
 ↓
Tool
 ↓
Environment
 ↓
Harness

M3
Harness
 ↓
Context
 ↓
Retrieval
 ↓
Memory
 ↓
Evaluation
```

到这里，你的 Agent 系统能力已经形成比较完整的一层。

而 M4 就应该发生一次明显的技术跃迁：

> **从 Agent Systems 进入 AI Systems：GPU → CUDA → Transformer Inference → KV Cache → Attention → Quantization → vLLM → SGLang → Distributed Inference。**

这也是整个6个月计划中，最需要补齐、同时最有可能把你与普通 Agent 开发者拉开差距的一段。
